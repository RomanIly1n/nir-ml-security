# Датасеты и бенчмарк для ML в обнаружении сетевых атак

Исследовательский проект посвящён оценке качества и ограничений сетевых датасетов, используемых для обучения и проверки методов машинного обучения (ML) в задачах обнаружения сетевых атак.

## Цель проекта

Разработать воспроизводимую методику аудита сетевых датасетов и экспериментальный бенчмарк, позволяющий исследовать, как качество данных, состав признаков и протоколы разбиения выборок влияют на результаты ML-моделей.

## Задачи исследования

- Изучить ограничения и известные проблемы общедоступных датасетов для обнаружения сетевых атак.
- Провести аудит CIC-IDS2017 и UNSW-NB15: изучить структуру, распределения классов, пропуски, дубликаты и другие особенности данных.
- Разработать правила разметки и документирования оснований для присвоения меток.
- Подготовить контролируемый набор сетевых данных и проверить согласованность разметки.
- Обучить базовые модели и оценить их качество по согласованным метрикам.
- Исследовать влияние признаков-подсказок и протоколов разбиения на результаты.
- Оценить переносимость моделей между датасетами на сопоставимых признаках.
- Обеспечить воспроизводимость экспериментов за счёт фиксации данных, параметров и программного окружения.

## Датасеты

На этапе аудита рассматриваются:

- **CIC-IDS2017** — в том числе набор CSV-файлов, распространяемый в архиве `GeneratedLabelledFlows.zip`.
- **UNSW-NB15** — для сравнительного анализа структуры, признаков и разметки.

Фактический состав полей и особенности конкретных копий датасетов проверяются в ходе аудита и не предполагаются заранее.

## Окружение

Для работы рекомендуется Python 3.11 или 3.12.

Создание виртуального окружения:

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.venv\\Scripts\\Activate.ps1
```

Активация в Linux и macOS:

```bash
source .venv/bin/activate
```

Установка зависимостей:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

## Работа с данными

- Исходные файлы хранятся отдельно от результатов обработки и не изменяются в ходе аудита.
- Для каждого набора данных фиксируются источник, версия или дата получения, условия использования и контрольная сумма, если она доступна.
- Очистка, фильтрация и преобразование данных выполняются воспроизводимым кодом.
- Подготовленные данные и результаты экспериментов хранятся отдельно от исходных файлов.
- Большие файлы датасетов не добавляются в Git. Каталоги `data/raw/` и `data/processed/` предназначены для локального хранения данных.
- Публикуются только материалы, распространение которых не нарушает лицензионные условия и ограничения источников.

## Принципы экспериментальной методики

При аудите проверяются структура и типы признаков, пропуски, бесконечные и подозрительные значения, дубликаты, константные столбцы и распределение классов.

В методике разметки предусмотрены три категории: `benign`, `attack` и `unknown`. Каждая метка должна иметь документированное основание. Записи с недостаточными основаниями для уверенной классификации относятся к `unknown` и не используются как обычные обучающие примеры.

Для оценки моделей предусматриваются отдельные протоколы разбиения по независимым запускам и по целым сценариям. Результаты этих протоколов анализируются раздельно. Междатасетные эксперименты выполняются на признаках, сопоставимость которых подтверждена по смыслу и способу вычисления.

## Текущий статус

Репозиторий находится на начальном этапе формирования. Подготовлена базовая структура для аудита датасетов, хранения документации и последующих экспериментов. Методика и экспериментальные результаты будут дополняться по мере выполнения исследования.
